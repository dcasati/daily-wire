# Architecture and decision record

```
sources.yaml ─▶ fetch (SSRF-safe, bounded) ─▶ normalize/reject ─▶ cluster ─▶ change detect ─▶ score+shortlist
   ─▶ evidence packets ─▶ writer (LLM | evidence-only) ─▶ verify (deterministic) ─▶ EPUB/MD/JSON/OPDS ─▶ gh-pages
```
Stages are plain functions in `src/daily_wire/` (`fetch`, `normalize`, `cluster`, `changes`, `rank`, `evidence`, `summarize`, `verify`, `epub`, `opds`, `publish`, orchestrated by `pipeline.run`). The whole run is deterministic given (config, fetched bytes, now), except the LLM call.

## Data contracts
- **Item**: id (sha256 of canonical URL), source, **origin** (original reporter), url, title, published (UTC), optional event_time (only if a feed states it; none do today), summary, region, category, ingested, reliability, flags.
- **Packet** per shortlisted event: event_id, section, status (new/updated), confidence, score, independent_origins, ≤3 evidence entries (source number, title, ≤280-char snippet, published), disagreements, gaps.
- **Writer output** (schema-validated): `{bluf, statements[{event_id,text,kind,refs}], watch[{indicator,significance,refs}]}`. Section placement, "Changes", sources and numbering are assigned by code, not the model.

## Decisions
1. **Flat modules, stdlib-first, one runtime dependency (PyYAML).** EPUB is a hand-built zip (no ebooklib), HTTP is `urllib`, RSS is `xml.etree` with DTD/entity refusal. Keeps the audit surface small (~1,400 lines).
2. **Deterministic selection before any LLM call.** Title-token Jaccard clustering (threshold 0.4, light stemming) and an additive score whose parts are stored per event (impact terms, scale, category, source quality, corroboration, novelty, Canada relevance). *Confidence* (low/moderate/high) is computed separately from *significance* and from independent origins: wire-credited copies share one origin and never corroborate each other. Trade-off: keyword/lexical methods miss paraphrases and non-English headlines; no embeddings, by design.
3. **LLM only writes, never selects or cites freely.** It sees ≤6,000 tokens of packets inside `<evidence>` delimiters with a system rule that this is data, and returns JSON. Provider interface is one method (`complete`), implemented for OpenAI-compatible `/chat/completions` (works with many vendors via `base_url`).
4. **Verification is code, not another model** (`verify.py`): citation resolves and belongs to the same event; numbers, capitalised names and assertive military/political verbs must appear in the cited evidence; ≥50% content-word overlap; low-confidence claims must be attributed; known disagreements must be disclosed; injection phrases/unknown URLs rejected; date/window consistency; word cap; BLUF ≤3 sentences. Failure → one retry with error feedback (`llm.max_attempts`) → evidence-only edition (headlines copied from sources, labelled) → if that fails, **no publication** and the previous edition remains with `health` flagging staleness. Limit: lexical grounding cannot catch a *reordered* or subtly distorted true-words claim.
5. **State in Git on the `gh-pages` branch** (`state.json`: event history incl. item IDs, HTTP validators, daily spend). Alternatives: SQLite (binary diffs, no benefit at this scale), Actions cache (evictable, not auditable), artifacts (expire). Costs: state is public (contains only public headlines/IDs); writes need `contents: write` (scoped to the publish job); concurrency is solved with a single workflow-level concurrency group, `cancel-in-progress: false`. State is written only after a successful publish, so a failed run re-sees the same items next time.
6. **Publishing to the `gh-pages` branch** (not `deploy-pages`) so archives and state persist in one place. `publish.py` writes only under the site dir (`_safe` path confinement, edition ids regex-checked) and validates the EPUB before writing. **Tradeoff:** Pages has no access control; editions are public. A secret URL is not security. If privacy matters, use a private Cloudflare/Tailscale-served host or a private repo with Pages on an Enterprise plan; the OPDS output is static files, so any static host works.
7. **Scheduling:** cron at 12:00 and 13:00 UTC plus `--require-hour` (local hour must equal 6 in America/Edmonton) handles DST without depending on newer scheduling features. If GitHub delays a run by >1 h the guard skips it; use manual dispatch to recover. `workflow_dispatch` is supported.
8. **Cost control:** worst-case cost (estimated input tokens + max output tokens at configured prices) is checked *before* every call against `max_daily_usd`, including spend already recorded that day; exceeding it hard-stops to evidence-only. Usage is stored in each edition's JSON and `status.json`.
9. **EPUB:** one XHTML document, EPUB 3 nav + NCX (KOReader/older readers), 1 small CSS file, no images/fonts/scripts, UTF-8. ~4 KB for the sample.
10. **Not done (deliberately):** no agent frameworks, vector DB, scraping, ISW/ACLED adapters (no confirmed public feed; ACLED requires credentials), translation, or paywalled content.

## Security notes
Least-privilege workflow permissions (read by default; write only in the publish job); secrets only via `secrets.*`; deps pinned (`pyproject.toml`) with Dependabot for pip and Actions (pin action SHAs when you adopt Dependabot); HTTPS only, no credentials/ports, every redirect hop and DNS answer must be public (`ipaddress.is_global`). **Residual risk:** DNS rebinding between check and connect; GitHub-hosted runners are ephemeral, which limits blast radius. Feed content is escaped in XHTML, URLs restricted to http(s), items with injection phrases are quarantined and never enter packets, and the model's output is verified against evidence rather than trusted.
